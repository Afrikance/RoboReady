# Priority scoring

I recommend not using a subjective "best government" score. Instead, score concrete sales attributes:

| Factor | Points |
| ----- | ----: |
| Population \>250K | \+5 |
| Budget \>\$500M | \+5 |
| Existing AI initiative | \+5 |
| Published AI policy | \+4 |
| Major technology department | \+3 |
| Major transportation infrastructure | \+3 |
| Public parking/garage network | \+2 |
| EV program | \+3 |
| Autonomous mobility activity | \+5 |
| Major public facilities | \+3 |
| Procurement opportunity currently open | \+7 |
| Existing vendor/contract vehicle | \+4 |
| Public innovation office | \+3 |

Then:

* 25+ \= Priority A  
* 15–24 \= Priority B  
* 8–14 \= Priority C  
* 0–7 \= Nurture

Those are sales-prioritization bands, not rankings of governments.

# The first 500 accounts

Rather than immediately trying to contact every government unit, the workbook should initially populate:

### State layer

* 50 state governments  
* 10–15 agencies/state \= approximately 500–750 agency accounts

### Local layer

* Largest counties  
* Largest cities  
* Major transit authorities  
* Airport authorities  
* Port authorities  
* Major utility/water districts  
* Major public facilities

Then expand to the complete Census government universe.

This is much more manageable than immediately attempting tens of thousands of local-government records.

## The important next build

The 50-state sheet above is the strategy layer. The next step is to turn it into the actual account-level prospect database by loading the current Census government-unit data and joining it to official state/local procurement and government websites.

That would produce records like:

`Maryland → Baltimore County → CIO → IT Director → Procurement Portal → StaffGPT Government Workforce → RoboReady Campus Assessment → verified source → outreach status`

rather than merely having "Maryland" in a spreadsheet.

The Census Bureau's current 2026 Government Units Listing is the right starting dataset for that expansion. Census.gov
